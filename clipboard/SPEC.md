# クリップボード — 仕様メモ（未着手）

目的: Mac と iPhone の間で、テキスト・画像を **Handoff（ユニバーサルクリップボード）より確実に** 受け渡す。Handoff は不安定なため、それに代わる仕組みを作る。研究用途（単位記号、表の変換など）に強いことも狙う。

状態: 仕様のみ。研究優先のため、トークンに余裕ができたら着手する。

## 方針
- まず **テキストの送受信だけ** の最小版（MVP）を作る。必要に応じて機能を足す。
- Webアプリ（PWA）として `clipboard/` に置く。ビルド不要の静的ファイル。
- 中継サーバーは使うが、**端末側で暗号化してから送る（エンドツーエンド暗号化）**。サーバーは中身を読めない。

## 仕組み
1. **ペアリング（最初の1回）**: Mac の画面に QR を出し、iPhone で読み取る。このとき暗号鍵を2台で共有する。鍵は端末内にだけ保存し、サーバーには送らない。
2. **中継**: Cloudflare（Workers + KV/Durable Objects）か Supabase の無料枠。ペアごとの「部屋ID」宛てに暗号文を置き、相手が取りに来る。保存期限を短くする（例: 24時間で自動削除）。
3. **送る操作を1アクションに**
   - iPhone: ショートカットアプリ + 背面タップで「今のクリップボードを送信」
   - Mac: ショートカットにキーボードショートカットを割り当て、⌘C の直後に1キーで送信
   - どちらもツールのURLに送信用のリンク/API を呼ぶ形にする（要調査）。
4. **受け取る**: アプリを開くと最新が出てタップでコピー。通知は後回し（Web Push は iOS で制約が多い）。

## Handoff と比べた利点
- 別ネットワーク（大学Wi-Fiとモバイル回線）でも動く。
- 履歴が残る。送れたかどうかが分かる。

## 制約・注意（Webアプリの限界）
- クリップボードをバックグラウンドで自動記録することはできない。ユーザー操作（貼り付け・ショートカット）が必要。
- iOS Safari はクリップボードの読み取りに許可が必要。ショートカットアプリ経由の方が確実な可能性がある。
- 中継サーバーを使うので、ルート `CLAUDE.md` の「ツールはデータを外部送信しない」の例外になる。**暗号化が前提**であることをREADMEに明記する。
- 無料アカウント（Cloudflare等）をユーザーが1つ作る必要がある。作成手順は着手時に初心者向けに案内する。
- 研究データ・機密は送らない運用を推奨（公開リポジトリのコードで動く、無料枠のサーバーのため）。

## フェーズ
1. **MVP**: ペアリング、テキスト送受信、直近の履歴
2. **研究向け機能**: 定型文/スニペット（φ ± ° μ Ω など）、全角⇄半角、単位換算（mm⇄in、rpm⇄rad/s）、Excel貼り付け→Markdown/LaTeX/CSV表、PDFコピーの余計な改行削除
3. **拡張**: 画像の送受信（写真寸法メモの書き出し画像を直接送る）、ピン留め・検索・タグ、履歴の自動削除設定

## 着手時の最初の確認
- 中継サーバーはどれにするか（Cloudflare か Supabase か）
- ショートカットアプリから送信する具体的な方法（URLスキーム/HTTPリクエスト）を先に小さく検証する
